# implementation

專門用於自主執行開發任務的引擎。它能將高階的計畫項目轉換為經過驗證、具備原子化提交（atomic commits）的程式碼變更。

## 工作流程 (原子化執行循環)

對於每個分配到的 Task ID，此技能必須嚴格遵循以下順序：

1. **上下文初始化 (Context Initialization)**：
    - 識別目標檔案與技術棧（例如：C#、Python、TypeScript）。
    - **自動風格注入**：立即調用 `activate_skill("coding-style")` 以載入偵測到技術棧的相關標準。**不可**跳過此步驟。
2. **實作 (Act)**：
    - 嚴格依照計畫中的「實作細節（Implementation Details）」與「實作方式（Approach）」進行精確的程式碼變更。
    - 保持載入的編碼風格中所定義的架構完整性。
3. **驗證 (Validate)**：
    - **編譯檢查**：執行專案的編譯指令（例如：`dotnet build`、`npm run build`）。系統必須處於可編譯狀態。
    - **測試檢查**：執行計畫中提到的特定單元測試或驗證指令。
    - **自我修復**：如果驗證失敗，嘗試在當前循環中診斷並修復錯誤。
4. **中止條件 (Fail-Safe)**：
    - 如果發生以下情況，必須**立即停止**所有後續任務並通知使用者：
        - 嘗試修復後編譯錯誤仍然存在。
        - 在計畫中發現關鍵的邏輯矛盾。
        - 單一 Task 影響超過 9 個檔案（原子化設計的安全門檻）。
5. **原子化提交 (Atomic Commit)**：
    - 僅在驗證成功**後**執行 git commit。
    - **雙源合成 (Dual-Source Synthesis)**：調用 `git-commit` 產生一個結合「計畫意圖」（來自任務描述）與「實體變更」（來自 `git diff`）的訊息。
    - **授權**：無需進一步確認即可執行提交（已由代理人工作流預先授權）。
6. **進度追蹤 (Progress Tracking)**：
    - 將計畫任務表中的「Status」欄位更新為 `Review`。
    - 如果是批次任務中的第一個任務，可以在執行期間將其設置為 `InProgress`。

## 指導方針
- **繁體中文**：使用繁體中文與使用者溝通。
- **原子性 (Atomicity)**：一個 Task ID = 一個 Commit。切勿將多個任務合併為單一提交。
- **依賴意識**：必須按照計畫定義的順序執行任務，以尊重邏輯依賴關係。
- **最小干預**：追求完全自主；僅在達到 Fail-Safe 中止條件時才請求使用者介入。
