## 共用欄位定義

跨多個案型使用的欄位，定義集中於此；各案型只列出本案型專屬欄位。

### 共通
- **欠缺條件** (`LackAmount`)：活動回傳值，整數。
  - 正值：距達標還差幾件 / 幾元
  - `0`：達標，可計算折扣
  - 負值：超過上限（OverLimit 案型適用，目前僅買一送一 / N件Y元），絕對值為超過件數

### 現折
- **是否首購折扣** (`IsFirstBuy`)：折扣明細上的標記（是 / 否），記錄此折扣是否屬於首購活動。
- **首購商品** (`IsUseNewMemberPromotion`)：購物車內商品的標記（是 / 否），由前端或上游服務在傳入購物車品項時設定，**最多只會有 1 個**。
- **首購會員標記** (`request.IsFirstBuy`)：請求層級欄位，由前端或上游服務傳入，表示「該會員當前是否符合首購條件」。

### 贈點
- **點數系統** (`promote_way`)：`1` = 福利點（`PxpayPoint`）、`2` = 全點（`PxpayPlusPoint`）。兩者計算邏輯相同，差別只在折抵記錄到不同點數系統。
- **訂單贈點總上限** (`MaxPointsPerOrder`)：跨贈點活動的累計上限；單位為「點」；正值表示截斷，0 = 不限。

## AC-現折-1 訂單滿件 — 現折金額

### 系統欄位定義
- **門檻條件** (`condition_amount`)：必填，單位為「件數」，必須為正整數。
- **折扣金額** (`item_quantity`)：必填，單位為「元」，必須為正整數。
- **可累折** (`is_cumulate`)：布林值（是／否）。
- **折扣上限** (`cumulate_limit`)：單位為「元」，若填 0 代表不設上限。

### 核心驗收標準

- **AC-滿件金-核心邏輯**：當購物車內適用此活動的商品總購買件數（非品項數，單一商品買多件需累計件數）大於或等於門檻條件時，觸發折扣計算。若未達門檻，活動不觸發，且必須回報欠缺條件 = 門檻條件 − 當前總件數。

- **AC-滿件金-累折機制**：
  - 當可累折為「否」時：不論總件數超過門檻多少倍，該活動算出的「總折扣金額」固定等於設定的折扣金額。
  - 當可累折為「是」時：計算觸發組數，公式為 觸發次數 = floor(總件數 / 門檻條件)（向下取整，不足一組的餘件不計）。「總折扣金額」= 觸發次數 × 折扣金額。

- **AC-滿件金-上限截斷**：若折扣上限 > 0，且算出的「總折扣金額」大於折扣上限時，系統必須強制將總折扣金額截斷並設定為該上限金額。

- **AC-滿件金-費用均攤**：此活動算出的總折扣金額，必須透過共用均攤邏輯按各適用商品的金額比例攤提回去，並在各商品下新增一筆折扣明細（記錄本活動編號、是否首購折扣 = 否）。

## AC-現折-2 訂單滿件 — 現折折數

### 系統欄位定義
- **門檻條件** (`condition_amount`)：必填，單位為「件數」，必須為正整數。
- **折數** (`item_quantity`)：必填，範圍為 0–100 的正整數（例如填 90 代表九折，即折抵金額為 100 − 90 = 10%）。
- **折扣上限** (`cumulate_limit`)：單位為「元」，若填 0 代表不設上限。
- **可累折** (`is_cumulate`)：布林值（是／否），但折數型不讀此欄位（見下方規則）。

### 核心驗收標準

- **AC-滿件折-核心邏輯**：當購物車內適用此活動的商品總購買件數大於或等於門檻條件時，觸發折扣計算。若未達門檻，活動不觸發，且必須回報欠缺條件 = 門檻條件 − 當前總件數。

- **AC-滿件折-折數型特殊行為（不讀可累折 Flag）**：折數型活動在計算時，**一律不讀取「可累折」flag**。不論該 flag 設定為「是」或「否」，系統均不區分觸發組數，一律以適用商品的總金額直接套用折數公式計算。計算公式：

  原始總折扣 = 適用商品總金額 × (100 − 折數) / 100

- **AC-滿件折-四捨五入規則**：折數計算結果若產生小數點，必須進行四捨五入（採半值往遠離 0 的方向進位，例如 .5 必須進位，未達 .5 則捨去），最終總折扣必須為整數。

- **AC-滿件折-上限截斷**：不論可累折為何，只要折扣上限 > 0，算出的總折扣金額超過該上限時，必須作為單筆折扣上限強制截斷並設定為該上限金額。

- **AC-滿件折-費用均攤**：算出的整數總折扣金額，必須透過共用均攤邏輯按各適用商品的金額比例攤提回去，並在各商品下新增一筆折扣明細（記錄本活動編號、是否首購折扣 = 否）。

## AC-現折-5 第N件 — 現折金額

### 系統欄位定義
- **組距件數** (`condition_amount`)：必填，單位為「件數」，**必須大於 1**（建立限制）；同時作為門檻判定與累折分組分母。
- **折扣金額** (`item_quantity`)：必填，單位為「元」，必須為正整數；意義為「每件最多可折抵金額」。
- **可累折** (`is_cumulate`)：布林值（是／否）。
- **折扣上限** (`cumulate_limit`)：單位為「元」，若填 0 代表不設上限。

> **建立限制**：適用範圍必須為「限定商品」、適用會員必為「全體會員」（不可首購）、不可選顯示折後價。

### 核心驗收標準

- **AC-N件金-核心邏輯**：當購物車內適用此活動的商品總購買件數 ≥ 組距件數時，觸發折扣計算。若未達門檻，活動不觸發，且必須回報欠缺條件 = 組距件數 − 當前總件數。

- **AC-N件金-取件邏輯**：計算前先將每件商品展開為一件一件（quantity 展開），計算各件的平均單價（總金額 / 數量，餘額補在最後一件），按平均單價由低到高排序，取最便宜的 N 件作為折扣標的：
  - 可累折 = 否：N = 1
  - 可累折 = 是：N = floor(總件數 / 組距件數)

- **AC-N件金-折扣計算**：每件各折 min(該件平均單價, 折扣金額)，逐件累加為總折扣金額。

- **AC-N件金-上限截斷**：可累折 = 是 且折扣上限 > 0 時，逐件累加過程中若累計總折扣超過上限，當下件折扣截斷至剩餘額度；超過上限後不再繼續累加。

- **AC-N件金-保留 $1 兜底**：若計算出的累計總折扣 ≥ 適用商品的總金額，預先降為「總金額 − 不同品項數」，保證每品項至少留 $1。

- **AC-N件金-費用均攤**：透過共用均攤邏輯按各適用商品的金額比例攤提；明細記錄本活動編號、是否首購折扣 = 否。

## AC-現折-6 第N件 — 現折折數

### 系統欄位定義
- **組距件數** (`condition_amount`)：必填，單位為「件數」，必須大於 1；門檻兼累折分組分母。
- **折數** (`item_quantity`)：必填，範圍為 0–100 的正整數。
- **可累折** (`is_cumulate`)：布林值（是／否）。
- **折扣上限** (`cumulate_limit`)：單位為「元」，若填 0 代表不設上限。

> **建立限制**：同「第N件 — 現折金額」。

### 核心驗收標準

- **AC-N件折-核心邏輯**：總件數 ≥ 組距件數時觸發；未達則欠缺條件 = 組距件數 − 當前總件數。

- **AC-N件折-取件邏輯**：同「第N件 — 現折金額」（展開、排序、按可累折取 1 件或 N 件）。

- **AC-N件折-折扣計算**：每件各折 該件平均單價 × (100 − 折數) / 100（四捨五入），逐件累加為總折扣金額。

- **AC-N件折-累折上限處理**：
  - 可累折 = 是 且折扣上限 > 0 時，逐件累加過程中若累計總折扣超過上限，當下件折扣截斷至剩餘額度；超過後不再累加。
  - 可累折 = 否 時，折扣上限作為「單筆折扣上限」，當下件折扣超過上限直接截斷至上限。

- **AC-N件折-保留 $1 兜底**：若累計總折扣 ≥ 適用商品總金額，預先降為「總金額 − 不同品項數」。

- **AC-N件折-費用均攤**：透過共用均攤邏輯按各適用商品的金額比例攤提；明細記錄本活動編號、是否首購折扣 = 否。

## AC-現折-7 首購滿件 — 現折金額

### 系統欄位定義
- **是否首購活動** (`is_first_buy`)：本案型固定為是。
- **門檻條件** (`condition_amount`)：系統強制為 `1`（建立限制）。
- **折扣金額** (`item_quantity`)：必填，單位為「元」，必須為正整數。
- **可累折** (`is_cumulate`)：系統強制為「否」（建立限制）。
- **折扣上限** (`cumulate_limit`)：單位為「元」，若填 0 代表不設上限。

> **建立限制**：適用條件必為訂單滿件（不可滿額 / 第N件）、適用範圍必為「限定商品」、適用會員必為「新會員尚未首購」。

### 核心驗收標準

- **AC-首購金-首購會員檢查**：若請求中「首購會員標記」為否，整個活動直接跳過，**不加入活動結果列表**。

- **AC-首購金-首購商品縮減**：進入計算前，系統會把適用商品縮減為「購物車內被標記為首購商品的那一件」（最多 1 件）。

- **AC-首購金-核心邏輯**：縮減後若存在首購商品（件數 ≥ 1，等同於達門檻 1）→ 達標；折扣金額 = 設定的折扣金額。

- **AC-首購金-保留 $1 兜底**：若折扣金額 ≥ 首購商品售價，預先降為「首購商品售價 − 1」，保證至少留 $1，超額部分靜默丟棄。

- **AC-首購金-上限截斷**：若折扣上限 > 0 且算出的折扣金額大於上限，截斷至上限金額。

- **AC-首購金-費用均攤**：折扣金額全攤在首購商品上（其他商品不分得）；明細記錄本活動編號、是否首購折扣 = 是。

- **AC-首購金-首購選擇器情境**：若首購會員標記 = 是、購物車內無首購商品，活動仍會被檢查並出現在活動結果列表（欠缺條件 = 0），但因攤提階段沒有首購商品 → 無商品分得折扣。此回傳形式作為前端「首購商品選擇器」的資料來源。

- **折扣上限** (`cumulate_limit`)：單位為「元」，若填 0 代表不設上限。

> **建立限制**：同「首購滿件 — 現折金額」。
>
> **折數型特殊行為**：與其他折數案型一致，計算公式不讀可累折 flag；折扣上限 > 0 仍作為單筆折扣上限。

### 核心驗收標準

- **AC-首購折-首購會員檢查**：若請求中「首購會員標記」為否，整個活動直接跳過，不加入活動結果列表。

- **AC-首購折-首購商品縮減**：進入計算前，系統會把適用商品縮減為「購物車內被標記為首購商品的那一件」（最多 1 件）。

- **AC-首購折-核心邏輯**：縮減後若存在首購商品（達門檻 1）→ 達標。折扣計算公式：

  折扣金額 = 首購商品售價 × (100 − 折數) / 100（四捨五入）

- **AC-首購折-上限截斷**：若折扣上限 > 0 且計算結果大於上限，截斷至上限金額。

- **AC-首購折-保留 $1 兜底**：若折扣金額 ≥ 首購商品售價，預先降為「首購商品售價 − 1」。

- **AC-首購折-費用均攤**：折扣全攤在首購商品上（其他商品不分得）；明細記錄本活動編號、是否首購折扣 = 是。

## AC-現折-9 買一送一（新案型）

### 系統欄位定義
- **門檻條件** (`condition_amount`)：系統固定存 `2`，使用者不需設定。
- **折扣金額** (`item_quantity`)：本案型不使用，存 `0`；折扣由系統從商品售價自動計算。
- **可累折** (`is_cumulate`)：布林值（是／否）。
- **觸發次數上限** (`cumulate_limit`)：單位為「次」，0 = 不限；當可累折 = 否時固定觸發 1 次，視為有效觸發上限 1 次。

### 核心驗收標準

- **AC-買一送一-首購商品排除**：購物車內被標記為「首購商品」的商品，從本活動的適用清單中排除。其餘符合適用範圍的商品為「實際適用商品」。

- **AC-買一送一-排除後 0 件不回傳**：若經首購商品排除（或同群組互斥規則排除）後，實際適用商品剩 0 件，本活動整個跳過，不加入活動結果列表（視為消費者所選商品都不在本活動適用範圍，畫面不顯示）。

- **AC-買一送一-達標條件**：實際適用商品的總購買件數必須同時滿足以下兩條件才達標：
  - 件數 ≥ 2（門檻條件）
  - 件數為偶數（避免奇數件半套）

- **AC-買一送一-未達標**：未達標時不折扣，且必須回報欠缺條件：
  - 件數 < 2：欠缺條件 = 2 − 件數
  - 件數 ≥ 2 但為奇數：欠缺條件 = 1（差 1 件達下個有效偶數）

- **AC-買一送一-觸發次數計算**：達標後實際觸發次數：
  - 有效觸發上限：可累折 = 否 → 1 次；可累折 = 是 → 觸發次數上限（0 時不限）
  - 可累折 = 否：固定 1 次
  - 可累折 = 是：min(floor(總件數 / 2), 觸發次數上限)；當觸發次數上限 = 0（不限）時為 floor(總件數 / 2)

- **AC-買一送一-超過上限（OverLimit）**：當總件數 > 有效觸發上限 × 2 時：
  - 不計算折扣
  - 回報欠缺條件 = -(總件數 − 有效觸發上限 × 2)（負值表「超過幾件」）
  - OverLimit 判定**優先於**未達標判定（奇數件、未達門檻）

- **AC-買一送一-折扣計算**：將所有實際適用商品按售價由低到高排序，取最便宜 N 件免費（N = 實際觸發次數）；折扣金額 = 這 N 件的售價合計。

- **AC-買一送一-費用均攤**：算出的折扣金額透過共用均攤邏輯按實際適用商品的金額比例攤提；明細記錄本活動編號、是否首購折扣 = 否。

## AC-現折-10 N件Y元（新案型）

### 系統欄位定義
- **門檻條件** (`condition_amount`)：必填，單位為「件數」，表示達門檻的最小件數。
- **每組件數** (`per_n_qty`)：必填，單位為「件」，本案型新增欄位；既是分組分母也是倍數檢查依據。
- **每組目標金額** (DB `per_n_price` / 回傳結構欄位 `PerNPrice`)：必填，單位為「元」，本案型新增欄位；表示「每組 N 件的目標總價」。前端取此值用於組合行銷標籤文字。
- **折扣金額** (`item_quantity`)：本案型不使用，存 `0`；折扣由實際售價與目標金額差動態計算。
- **可累折** (`is_cumulate`)：布林值（是／否）。
- **觸發次數上限** (`cumulate_limit`)：單位為「次」，0 = 不限；當可累折 = 否時固定觸發 1 次，視為有效觸發上限 1 次。

> **欄位設計備註**：門檻條件與每組件數為「預開欄位」設計 — 系統同步來源寫入相同值（總部來源不支援拆分設定），但保留未來分開設定的擴展性。計算邏輯兩欄位都讀，不假設兩欄位相等。

### 核心驗收標準

- **AC-N件Y元-適用範圍**：本案型不對首購商品做排除（與買一送一不同）。同群組互斥規則仍適用 — 若經規則排除後實際適用商品剩 0 件，活動整個跳過，不加入活動結果列表。

- **AC-N件Y元-達標條件**：實際適用商品的總購買件數必須同時滿足以下兩條件才達標：
  - 件數 ≥ 門檻條件
  - 件數為「每組件數」的整數倍

- **AC-N件Y元-未達標**：未達標時不折扣，且必須回報欠缺條件。設 `target = ceil(max(總件數, 門檻條件) / 每組件數) × 每組件數`（即同時滿足「≥ 門檻」與「為每組件數整數倍」的最小件數）：
  - 欠缺條件 = target − 總件數

- **AC-N件Y元-觸發次數計算**：達標後：
  - 自然觸發次數 = 總件數 / 每組件數
  - 有效觸發上限：可累折 = 否 → 1 次；可累折 = 是 → 觸發次數上限（0 時不限）
  - 實際觸發次數：可累折 = 否 → 固定 1；可累折 = 是 → min(自然觸發次數, 觸發次數上限)；觸發次數上限 = 0 時不限

- **AC-N件Y元-超過上限（OverLimit）**：當總件數 > 有效觸發上限 × 每組件數時：
  - 不計算折扣
  - 回報欠缺條件 = -(總件數 − 有效觸發上限 × 每組件數)（負值表「超過幾件」）
  - OverLimit 判定**優先於**未達標判定

- **AC-N件Y元-取件邏輯**：達標後將所有實際適用商品按售價由低到高排序，取最便宜 「實際觸發次數 × 每組件數」件作為折扣標的（比照買一送一選件方式）。

- **AC-N件Y元-折扣計算**：折扣金額 = 取出的件數實際售價合計 − (實際觸發次數 × 每組目標金額)。

- **AC-N件Y元-反向折扣保護**：若折扣金額 ≤ 0（最便宜的件數合計 ≤ 觸發次數 × 目標金額），本活動不套用，避免反向折扣讓消費者多付。

- **AC-N件Y元-費用均攤**：套用時的折扣金額透過共用均攤邏輯按所有實際適用商品的金額比例攤提；明細記錄本活動編號、是否首購折扣 = 否。

- **AC-N件Y元-前端標籤資料**：活動回傳結果必須帶有「每組件數」與「每組目標金額」兩個欄位，讓前端能組合「N件Y元」行銷標籤文字。

## AC-現折-11 共用均攤邏輯（AssignPromotionDiscount / AssignCouponDiscount）

> 說明：折扣金額算出後，透過共用均攤邏輯按金額比例分配回各適用商品。現折活動與折價券共用此邏輯（差別只在折抵記錄到不同欄位）。

### 核心驗收標準

- **AC-均攤-比例分配**：第一輪攤提依「商品折抵後金額」由大到小逐一處理，每件依比例算出該分得的折扣金額：每件折抵 = Round(該件金額 / 適用商品總金額 × 總折扣金額)（採半值往遠離 0 進位）。

- **AC-均攤-保留 $1**：每件商品攤後至少保留 $1。若依比例算出的折抵金額會讓某件商品低於 $1，截斷至「該件金額 − 1」。

- **AC-均攤-第一輪殘餘**：第一輪可能因四捨五入未分完所有折扣，殘餘進入第二輪。

- **AC-均攤-第二輪補金額最高**：第二輪將殘餘折扣分配給金額最高的商品；多件並列最高時補給排序第一件。第二輪也須保留 $1。

- **AC-均攤-未輪詢不分**：第一輪若剩餘折扣已歸 0，未輪詢到的商品（通常為金額最小者）不分得折扣。

- **AC-均攤-第二輪丟棄**：若第二輪所有商品都已剩 $1，無可分配對象，剩餘折扣靜默丟棄。

- **AC-均攤-捨入補 $1**：第一輪某商品依比例算出的折扣為 $0 但仍有剩餘折扣時，強制補 $1 給該商品（保證輪詢到的商品至少分到 $1）。

## AC-現折-12 Handler 整合層

> 兩個進入點共用此章節 AC：購物車試算階段（前端讀）、訂單成立階段（Order 服務讀）。

### 系統欄位定義

> 跨章節共用的整合層欄位／概念對應表。
>
> - **試算進入點** (`GetCalculateDiscountResultQueryHandler`)：前端在購物車畫面呼叫的 API；計算所有現折／折價券／贈點並回傳結果
> - **成單進入點** (`CalculatePromotionDiscountCommandHandler`)：Order 服務在訂單成立時呼叫的 API；只計算現折攤提結果
> - **全站排除快取** (`disableAllDiscount`)：標記不適用任何折扣的商品清單
> - **組合商品** (`IsComboShipment`)：商品標記為組合包成員，不適用現折活動
> - **OverLimit 活動清單** (`OverLimitPromotionIds`)：成單階段回傳結構新增的欄位，列出觸發超過上限的活動編號

### 核心驗收標準

#### 一、排序與優先序

- **AC-整合-排序-優先序表**：現折活動按 plan.md「折扣套用順序與折上折風控」表的優先序逐一處理。會員群組（首購）→ 商品現折群組（買一送一 → N件Y元 → 滿件 → 第N件）→ 訂單滿額群組。同群組內人工活動優先於系統同步活動。

- **AC-整合-排序-同群組互斥（per-product）**：對每個商品而言，同個折扣群組最多只有一個現折活動生效。某活動對某商品生效後，該商品在該群組的席位被佔用，後續同群組活動對該商品跳過。

- **AC-整合-排序-不同群組可並存**：對同一商品，會員群組 + 商品現折群組 + 訂單滿額群組可同時各生效一個。

- **AC-整合-排序-不需測組合**：以下組合由前提保證不發生，不需測：
  - 人工 + 人工 同商品：由現行檔期衝突檢核排除
  - 系統同步 + 系統同步 同商品：由「同商品在系統同步活動內最多 1 個」前提排除
  - 會員 / 訂單滿額群組同商品多活動：由前提保證最多 1 個

#### 二、累積扣減效應

- **AC-整合-累積扣減**：前活動算完折扣攤提後，後續活動看到的「商品折抵後金額」已是前活動扣減後的金額。對「金額型」門檻判定與計算（如訂單滿額）會影響達標與否與折扣計算 base。

#### 三、首購相關

- **AC-整合-首購-會員標記跳過**：請求中「首購會員標記」為否時，所有首購活動直接跳過，不加入活動結果列表。

- **AC-整合-首購-首購商品限定**：首購活動於攤提階段只折給「首購商品」（其他商品不分得首購折扣），即便活動的適用商品涵蓋多個。

- **AC-整合-首購-首購選擇器情境**：首購會員標記 = 是 但購物車內無首購商品時，首購活動仍會出現在活動結果列表（達標、無商品攤到折扣），作為前端「首購選擇器」資料來源。

#### 四、商品篩選

> 篩選規則套用範圍：
> - **全站排除快取**：試算階段（現折 + 贈點）與成單階段（現折）**都套用** — 確保試算 / 成單金額一致，避免消費糾紛
> - **組合商品**：試算階段（現折 + 贈點）與成單階段（現折）**都套用**
> - **數量為 0**：所有計算階段都套用
>
> 註：落帳階段（贈點，`OrderWasPaidEventHandler`）目前不過濾全站排除快取與組合商品，屬另一議題，本次需求不動。

- **AC-整合-篩選-全站排除**：商品在全站排除快取內時，從現折與贈點活動的適用清單中移除；試算階段與成單階段邏輯一致。

- **AC-整合-篩選-組合商品**：商品被標記為「組合商品」時，不適用所有現折與贈點活動；試算階段與成單階段邏輯一致。

- **AC-整合-篩選-數量為 0**：購物車中商品數量為 0 時，不參與所有計算（現折、贈點）。

#### 五、結果回傳

- **AC-整合-結果-未達門檻仍回傳**：未達門檻的活動仍出現在活動結果列表（折扣 = 0、欠缺條件 > 0、適用商品清單帶出活動原始設定），讓前端能提示「差 N 件 / N 元可達優惠」。

- **AC-整合-結果-排除後 0 件不回傳**：經首購商品排除或同群組互斥規則排除後實際適用商品剩 0 件的活動，**整個跳過**，不加入活動結果列表（買一送一 / N件Y元 適用）。

- **AC-整合-結果-OverLimit 回傳訊號**：
  - 試算階段：回傳活動結果含「欠缺條件 < 0」，前端讀此訊號顯示「已達優惠上限」訊息，引導消費者調整數量。
  - 成單階段：回傳結構新增「OverLimit 活動清單」，列出觸發 OverLimit 的活動編號；Order 服務看到清單非空時擋下訂單並寫 log。

- **AC-整合-結果-未達門檻差距回報**：欠缺條件依案型表達單位（件數型回件數、金額型回元）。

#### 六、多案型混合情境

- **AC-整合-混合-跨群組共存**：不同群組的多個活動可同時對同一張訂單生效。例如：首購活動（會員群組）+ 買一送一（商品現折群組）+ 訂單滿額（訂單滿額群組）可疊加。

- **AC-整合-混合-現折影響贈點 base**：現折活動先算完並攤提後，後續贈點活動看到的商品金額是折抵後金額；贈點門檻判定與計算 base 都以折抵後金額為準。

#### 七、現折對贈點與折價券的影響

- **AC-整合-現折影響贈點**：
  - **件數型贈點**（條件類型 = 滿件 + 贈點方式 = 點數）：贈點以件數判定門檻與計算，現折**不改件數** → **不受現折影響**
  - **金額型贈點**（條件類型 = 滿額）/ **百分比型贈點**（贈點方式 = 百分比）：贈點以金額判定 / 計算，現折改金額 → **受現折影響**，依折抵後金額判定門檻與計算贈點

- **AC-整合-現折影響折價券**：折價券攤提發生在現折之後；折價券 base 為現折後的商品金額。

## AC-贈點-1 訂單滿件 — 贈點數

### 系統欄位定義
- **門檻條件** (`condition_amount`)：必填，單位為「件數」，必須為正整數。
- **贈點數** (`item_quantity`)：必填，單位為「點」，必須為正整數。
- **可累贈** (`is_cumulate`)：布林值（是／否）。
- **單筆贈點上限** (`cumulate_limit`)：單位為「點」；正值表示截斷上限，0 = 不限（詳細規則見 [AC-贈點-9](#ac-贈點-9-上限與邊界共用)）。

### 核心驗收標準

- **AC-滿件點-核心邏輯**：當購物車內適用此活動的商品總購買件數 ≥ 門檻條件時，觸發贈點。若未達門檻，活動不觸發，欠缺條件 = 門檻條件 − 當前總件數。

- **AC-滿件點-累贈機制**：
  - 可累贈 = 否：不論總件數超過門檻多少倍，贈點數固定等於設定的贈點數。
  - 可累贈 = 是：觸發次數 = floor(總件數 / 門檻條件)（向下取整，餘件不計）；贈點數 = 觸發次數 × 設定的贈點數。

- **AC-滿件點-上限截斷**：詳見 [AC-贈點-9 上限與邊界（共用）](#ac-贈點-9-上限與邊界共用)。

## AC-贈點-9 上限與邊界（共用）

> 跨所有贈點案型適用的上限與行為規則。

### 系統欄位定義
- **單筆贈點上限** (`cumulate_limit`)：單位為「點」；正值表示截斷上限，0 = 不限。
- **訂單贈點總上限** (`MaxPointsPerOrder`)：見 [共用欄位定義 → 贈點](#贈點)。

### 核心驗收標準

- **AC-贈點-單筆上限截斷**：若單筆贈點上限 > 0 且算出的贈點數超過上限，截斷至上限。
  - **點數型**（AC-贈點-1、3、5、7）：對「可累贈 = 是」時的累積贈點數做截斷
  - **百分比型**（AC-贈點-2、4、6、8）：百分比型公式本身不讀「可累贈」flag，但「單筆贈點上限 > 0」時仍作為**單筆贈點上限截斷**（不分可累贈 flag 都生效）

- **AC-贈點-訂單總上限**：所有贈點活動累計贈點數不超過「訂單贈點總上限」；超過時截斷。

- **AC-贈點-不參與攤提**：贈點計算不影響商品折抵金額；攤提結果不分配給各商品（贈點記錄在訂單整體）。
  - 試算階段：依序處理現折 → 折價券 → **贈點**（最後）
  - 落帳階段：**僅處理贈點**
  - 成單階段：**不處理贈點**（贈點在落帳階段才算）

## AC-折價券-1 折價券攤回（迴歸保護）

> 範圍：本次需求不動折價券邏輯，但折價券攤回（`AssignCouponDiscount`）與共用均攤邏輯結構幾乎相同（差別只在折抵記錄到 `CouponDiscountAmount` / `Coupon` 物件），本章列出折價券現行行為作迴歸保護。
>
> 折價券只在試算階段（前端 Handler）處理；成單階段（服務 Handler）不處理折價券。

### 系統欄位定義
- **折價券 ID** (`CouponId`)：請求帶入的折價券識別碼。
- **折價券適用商品** (`CouponProductIds`)：請求帶入的可套用商品清單。
- **折扣金額**：折價券設定的總折扣金額，由 `GetCouponDiscountAmount` 先計算（含門檻判定 / 折數 / 上限）。

### 核心驗收標準

- **AC-折價券-計算階段 cap**：算出總折扣後，若總折扣 > 適用商品總金額，先 cap 至商品總金額再進入攤回。**cap 後攤回仍可能因「每件保留 $1」限制 silent drop 剩餘折扣**（攤回後實際生效金額可能 < cap 後的金額）。

- **AC-折價券-比例攤回**：採與現折共用均攤邏輯相同的兩輪攤提邏輯（按金額大到小依比例分、保留 $1、第一輪殘餘進第二輪補金額最高商品、捨入補 $1）。

- **AC-折價券-折抵記錄**：折抵金額記錄到商品的 `CouponDiscountAmount`；折價券明細物件記錄折價券 ID 與折扣金額（一張折價券一個物件，非 list）。

- **AC-折價券-排除規則**：適用商品清單會先排除「折價券排除快取」內的商品，再進入攤回。
