**備註：**
- `is_cumulate` 在現存**折數**案型的 `GetPromotionRebateAmount` 裡不讀取，標 —；第N件折數例外（`GetNthDiscountAmount` 用它決定取幾件）
- `cumulate_limit` 語義依案型不同：金額案型為累計折扣金額上限；折數案型為單筆折扣金額上限；買一送一與 N件Y元為每筆訂單限觸發次數（0 = 不限；買一送一另若 `is_cumulate = false` 時固定為 1）
- `condition_amount` 買一送一固定存 `2`（觸發門檻為 2 件）；買N件Y元存門檻件數
- `item_quantity` / `quantity_type` N件Y元不使用，折扣由 `per_n_price` 與商品售價動態計算，存 `0`
- `per_n_qty` 買N件Y元的每N件分組數，搭配 `condition_amount` 使用：`condition_amount` 為進入門檻，`per_n_qty` 為觸發分母
- `per_n_price` 買N件Y元的 Y元（每N件的目標總價）；折扣 = 實際N件售價合計 − `per_n_price`，由使用者在後台輸入

## 三、新案型折扣計算邏輯

### 買一送一

**首購商品排除**：購物車中標記為首購商品（`IsUseNewMemberPromotion = true`）的商品從買一送一活動的 `checkItems` 中排除。其餘適用商品仍照常參與門檻判斷與折扣計算。

**per-product 排除後 0 件 → 整個跳過**：經 per-product 規則（或首購商品排除）後，若 Y 適用商品剩 0 件（例如其他現折活動已折抵掉所有 Y 適用商品），則 Y 整個活動跳過，**不加入** `result.DiscountPromotions`（視為消費者選的商品都不在 Y 適用範圍，畫面不顯示）。差別於「未達門檻」（適用商品 > 0 件但件數不足）仍回傳 `LackAmount`。

排除後，購物車內符合活動的商品**總件數**必須**同時**滿足兩條件才達標：
1. 總件數 >= `condition_amount`（固定存 `2`）
2. 總件數為偶數（`總件數 % 2 == 0`，避免奇數件半套）

任一條件不滿足都不折扣，且回傳 `LackAmount`（差幾件達下個有效偶數）：
- 件數 < 2：`LackAmount = 2 − 總件數`
- 件數 >= 2 但為奇數：`LackAmount = 1`

達標後：
1. 將所有符合活動的商品混合，按售價由低到高排序
2. OverLimit 判定：
   - `is_cumulate = false`：有效觸發上限為 1 次；若總件數 > `1 × 2`，判定 OverLimit，不計算折扣
   - `is_cumulate = true` 且 `cumulate_limit > 0`：若總件數 > `cumulate_limit × 2`，判定 OverLimit，不計算折扣
   - `is_cumulate = true` 且 `cumulate_limit = 0`：不限上限，不做 OverLimit 判定
3. 計算實際觸發次數：
   - `is_cumulate = false`：固定為 1
   - `is_cumulate = true`：`cumulate_limit > 0 ? min(總件數 / 2, cumulate_limit) : 總件數 / 2`（`cumulate_limit = 0` 為不限；達標時件數必為偶數，整除無餘）
4. 取最便宜的 N 件免費（N = 實際觸發次數）；折扣 = 這 N 件的售價合計

加總後由 `AssignPromotionDiscount` 按金額比例攤回所有符合商品。

---

### N件Y元

**per-product 排除後 0 件 → 整個跳過**：同買一送一規則。經 per-product 規則排除後，若 Y 適用商品剩 0 件，則 Y 整個活動跳過，**不加入** `result.DiscountPromotions`（視為消費者選的商品都不在 Y 適用範圍，畫面不顯示）。差別於「未達門檻」「件數不為 `per_n_qty` 倍數」（適用商品 > 0 件但條件不符）仍回傳 `LackAmount`；「折扣 ≤ 0」則不回傳活動結果，避免前端顯示無實質優惠。

購物車內符合活動的商品**總件數**必須**同時**滿足兩條件才達標：
1. 總件數 >= `condition_amount`（達門檻）
2. 總件數 為 `per_n_qty` 的整數倍（`總件數 % per_n_qty == 0`）

任一條件不滿足都不折扣。達標後：

1. 自然觸發次數 = 總件數 / `per_n_qty`
2. OverLimit 判定：
   - `is_cumulate = false`：有效觸發上限為 1 次；若總件數 > `1 × per_n_qty`，判定 OverLimit，不計算折扣
   - `is_cumulate = true` 且 `cumulate_limit > 0`：若總件數 > `cumulate_limit × per_n_qty`，判定 OverLimit，不計算折扣
   - `is_cumulate = true` 且 `cumulate_limit = 0`：不限上限，不做 OverLimit 判定
3. 實際觸發次數：
   - `is_cumulate = false`：固定為 1
   - `is_cumulate = true`：`cumulate_limit > 0 ? min(自然觸發次數, cumulate_limit) : 自然觸發次數`（`cumulate_limit = 0` 為不限）
4. 將所有符合活動的商品混合，按售價由低到高排序，取最便宜 `實際觸發次數 × per_n_qty` 件（比照買一送一的選件方式）
5. 折扣 = 這些件的實際售價合計 − (`實際觸發次數 × per_n_price`)
6. **若折扣 ≤ 0（商品實際售價合計 ≤ 觸發次數 × per_n_price），活動不套用且不回傳活動結果**（避免反向折扣讓客戶多付，也避免前端顯示無實質優惠）
7. 加總後由 `AssignPromotionDiscount` 按金額比例攤回所有符合商品

> `is_cumulate` 與 `cumulate_limit` 比照買一送一：先看 `is_cumulate` flag，若為 false 則固定觸發 1 組，且超過 `1 × per_n_qty` 件視為 OverLimit；若為 true 才看 `cumulate_limit` 是否截斷。

> 範例（`per_n_qty = 2`、`per_n_price = $50`、買 6 件各 $100）：
> - `is_cumulate = false`：有效觸發上限為 1 組（2 件），買 6 件 > 2 件 → OverLimit，不計算折扣
> - `is_cumulate = true, cumulate_limit = 0`：3 組觸發（6 件全參與），折扣 = $600 − $150 = $450
> - `is_cumulate = true, cumulate_limit = 2`：2 組觸發（4 件參與），折扣 = $400 − $100 = $300

> `condition_amount` 與 `per_n_qty` 雙欄位用途：`condition_amount` 為進入資格的件數門檻；`per_n_qty` 為觸發分母兼倍數檢查依據。例如門檻=4、`per_n_qty`=2：買 4 件觸發 2 組、買 6 件觸發 3 組、買 5 件因非 2 的倍數不觸發。

> **未達標時 `LackAmount` 計算**：設 `target = ceil(max(總件數, condition_amount) / per_n_qty) × per_n_qty`（即同時滿足『>= 門檻』與『為 per_n_qty 整數倍』的最小件數），`LackAmount = target − 總件數`。例如門檻=4、`per_n_qty`=2、買 5 件：target = 6，LackAmount = 1；門檻=5、`per_n_qty`=2、買 4 件：target = 6（因 5 非 2 的倍數，需到下個倍數 6），LackAmount = 2。

## 四、DB 異動總結

### 新增欄位（`promotion` table）

| 欄位名稱 | 型別 | Default | 說明 |
|---------|------|---------|------|
| `per_n_qty` | int | 0 | N件Y元：每N件分組數（觸發分母）；非N件Y元案型存 `0` |
| `per_n_price` | int | 0 | N件Y元：每N件的目標總價（Y元）；非N件Y元案型存 `0` |

### 新增 Enum 選項

| Enum | 新增值 | 說明 |
|------|--------|------|
| `PromotionConditionType` | `BuyOneGetOne = 6` | 買一送一 |
| `PromotionConditionType` | `NItemsYPrice = 7` | 買N件Y元 |

### 現有欄位語義擴充（不新增欄位）

| 欄位 | 現行語義 | 擴充後語義 |
|------|---------|-----------|
| `cumulate_limit` | 金額案型：累計折扣上限；折數案型：單筆折扣上限 | 同上；買一送一與 N件Y元：每筆訂單觸發次數上限（0 = 不限；`is_cumulate = false` 時固定觸發 1 組，且以 1 組作為有效觸發上限） |
| `creator` | 建立者 userId | 同上；系統建立（總部轉入）存 `"system"`（與現有多個 Table 慣例一致） |
