## 二、折扣欄位計算使用矩陣

| 欄位 | 滿件/金 | 滿件/折 | 滿額/金 | 滿額/折 | 第N件/金 | 第N件/折 | 首購/金 | 首購/折 |
|---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| `promote_way` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| `condition_type` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| `condition_amount` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| `quantity_type` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| `item_quantity` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| `is_cumulate` | ✅ | — | ✅ | — | ✅ | ✅ | ✅ | — |
| `cumulate_limit` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| `is_first_buy` | — | — | — | — | — | — | ✅ | ✅ |

**欄位縮寫對照：**
- 滿件 = 訂單滿件、滿額 = 訂單滿額、第N件 = 滿N件折、首購 = 首購滿件
- 金 = 現折金額（`quantity_type = 3`）、折 = 現折折數（`quantity_type = 4`）

**備註：**
- `is_cumulate` 在**折數**案型的 `GetPromotionRebateAmount` 裡不讀取，標 —；但第N件折數例外，`GetNthDiscountAmount` 用它決定取幾件，故仍為 ✅
- `cumulate_limit` 所有案型都讀取，語義不同：金額案型為累計折扣上限；折數案型為單筆折扣上限

## 三、各案型折扣計算欄位使用說明

### 訂單滿件 — 現折(金額)

購物車內符合活動的商品**總件數** >= `condition_amount` 才達標。

達標後：
- `is_cumulate = false`：不論買幾件，固定折 `item_quantity` 元
- `is_cumulate = true`：每湊滿一次門檻就多折一次，折扣 = `item_quantity × floor(總件數 / condition_amount)`，超過 `cumulate_limit` 就截斷

---

### 訂單滿件 — 現折(折數)

購物車內符合活動的商品**總件數** >= `condition_amount` 才達標。

達標後對折後總金額乘以折扣率，折扣金額 = `折後總金額 × (100 - item_quantity) / 100`。`is_cumulate` 對折數計算無效。`cumulate_limit > 0` 時作為這筆訂單的折扣金額上限。

---

### 訂單滿額 — 現折(金額)

符合活動的商品**折後總金額** >= `condition_amount` 才達標。

達標後：
- `is_cumulate = false`：不論總金額多少，固定折 `item_quantity` 元
- `is_cumulate = true`：每湊滿一次門檻金額就多折一次，折扣 = `item_quantity × floor(折後總金額 / condition_amount)`，超過 `cumulate_limit` 就截斷

---

### 訂單滿額 — 現折(折數)

符合活動的商品**折後總金額** >= `condition_amount` 才達標。

達標後對折後總金額乘以折扣率，折扣金額 = `折後總金額 × (100 - item_quantity) / 100`。`is_cumulate` 對折數計算無效。`cumulate_limit > 0` 時作為這筆訂單的折扣金額上限。

---

### 第N件 — N件折金額

符合活動的商品**總件數** >= `condition_amount` 才達標。達標後進入 `GetNthDiscountAmount`：

1. 把所有符合商品展開成一件一件，每件算出平均單價（總金額 / 數量，餘額補在最後一件）
2. 按平均單價由低到高排序，取最便宜的幾件作為折扣標的：
   - `is_cumulate = false`：取最便宜的 1 件
   - `is_cumulate = true`：取最便宜的 `floor(總件數 / condition_amount)` 件
3. 每件各折 `min(該件平均單價, item_quantity)` 元，逐件累加；超過 `cumulate_limit` 就截斷
4. 若累計總折扣 ≥ 商品折後總金額，預先降為 `折後總金額 − 不同品項數`（保證每品項至少留 $1）
5. 加總後由 `AssignPromotionDiscount` 按金額比例攤回所有符合商品

**建立限制**（`SavePromotionCommandVerification` 強制）：
- `ScopeType` 必為「限定商品」（不可全站）
- `ConditionAmount` 必 **> 1**（門檻至少 2 件）
- `MemberUseType` 必為「全體會員」（不可首購）
- `IsShowDiscountPrice` 必為 `false`（不可選顯示折後價）

> `condition_amount` 有雙重用途：① 件數門檻判斷；② `is_cumulate = true` 時作為計算取幾件的分母

> ⚠️ **已知缺陷**：`is_cumulate = true` 且 `cumulate_limit = 0`（=不限）時，迴圈內的截斷判斷缺少 `cumulate_limit > 0` 守衛，會把每件折扣誤截為 $0，最終折扣 = $0。對應測試 AC-N件金-3 已標註。

---

### 第N件 — N件折折數

符合活動的商品**總件數** >= `condition_amount` 才達標。達標後進入 `GetNthDiscountAmount`：

1. 把所有符合商品展開成一件一件，每件算出平均單價（總金額 / 數量，餘額補在最後一件）
2. 按平均單價由低到高排序，取最便宜的幾件作為折扣標的：
   - `is_cumulate = false`：取最便宜的 1 件
   - `is_cumulate = true`：取最便宜的 `floor(總件數 / condition_amount)` 件
3. 每件各折 `該件平均單價 × (100 - item_quantity) / 100` 元，逐件累加；超過 `cumulate_limit` 就截斷
4. 若累計總折扣 ≥ 商品折後總金額，預先降為 `折後總金額 − 不同品項數`（保證每品項至少留 $1）
5. 加總後由 `AssignPromotionDiscount` 按金額比例攤回所有符合商品

**建立限制**：同上「第N件 — N件折金額」（`ScopeType` = 限定商品、`ConditionAmount` > 1、`MemberUseType` = 全體會員、`IsShowDiscountPrice` = false）。

> `condition_amount` 有雙重用途：① 件數門檻判斷；② `is_cumulate = true` 時作為計算取幾件的分母

> ⚠️ **已知缺陷**：`is_cumulate = true` 且 `cumulate_limit = 0`（=不限）時，迴圈內的截斷判斷缺少 `cumulate_limit > 0` 守衛，會把每件折扣誤截為 $0，最終折扣 = $0。對應測試 AC-N件折-4 已標註。

---

### 首購滿件 — 現折(金額)

`is_first_buy = true`。門檻與折扣計算邏輯與**訂單滿件 — 現折(金額)相同**：總件數 >= `condition_amount` 才達標；`is_cumulate` 決定是否累折；折扣 = `item_quantity`（不累折）或 `item_quantity × floor(總件數 / condition_amount)`（累折），超過 `cumulate_limit` 截斷。

**建立限制**（`SavePromotionCommandVerification` 強制）：
- `ConditionType` 必為訂單滿件（不可滿額 / 第N件）
- `ConditionAmount` 必為 `1`（門檻 = 1 件）
- `IsCumulate` 必為 `false`（不可累折）
- `ScopeType` 必為「限定商品」

額外限制（由 `is_first_buy` 控制）：
1. 前端傳入 `IsFirstBuy = false` 時整個活動直接跳過，不進入計算
2. 進入計算前 `checkItems` 已縮減為前端標記 `IsUseNewMemberPromotion` 的那一件商品
3. `AssignPromotionDiscount` 攤提對象同樣限縮為該商品，折扣不攤給其他商品

> 受建立限制：實務上 `condition_amount` 恆為 1、`is_cumulate` 恆為 false，因此「累折分支」與「未達門檻」不會發生（首購商品至少 1 件即達標）。

---

### 首購滿件 — 現折(折數)

`is_first_buy = true`。門檻與折扣計算邏輯與**訂單滿件 — 現折(折數)相同**：總件數 >= `condition_amount` 才達標；折扣金額 = `折後總金額 × (100 - item_quantity) / 100`；`is_cumulate` 無效；`cumulate_limit > 0` 時為單筆上限。

**建立限制**：同上「首購滿件 — 現折(金額)」（`ConditionType` = 訂單滿件、`ConditionAmount` = 1、`IsCumulate` = false、`ScopeType` = 限定商品）。

額外限制（由 `is_first_buy` 控制）：
1. 前端傳入 `IsFirstBuy = false` 時整個活動直接跳過，不進入計算
2. 進入計算前 `checkItems` 已縮減為前端標記 `IsUseNewMemberPromotion` 的那一件商品
3. `AssignPromotionDiscount` 攤提對象同樣限縮為該商品，折扣不攤給其他商品

> 首購不是獨立的 `condition_type`，它是 `OrderQuantity(1)` 加上 `is_first_buy = true` 的變型。

## 四、折扣攤提共用規則

所有案型算出總折扣金額後，都由 `AssignPromotionDiscount` 統一攤提到參與活動的商品上。流程分兩輪：

> **排序的平手規則**：兩輪都依折抵後金額由大到小排序，若多件並列，依輸入順序取第一件（LINQ stable sort 保留原始順序）。

### 第一輪：依比例分配（依折抵後金額由大到小）

將符合商品由金額大到小排序，逐件計算分配額：

1. 該件分配額 = `Round(該件折抵後金額 / 全部商品總額 × 總折扣)`
2. 落地規則：
   - 一般情況：採上步算出的分配額
   - 若分配額捨入為 $0、但仍有剩餘折扣，強制補 $1
   - 若分配後該件折抵後 < $1（折扣超過售價），改為「該件金額 − $1」（每件最少保留 $1）
3. 每處理一件就扣減剩餘折扣，**若剩餘折扣歸 0 立即結束本輪**
4. 結束時尚未輪詢到的商品不分得任何折扣

### 第二輪：分配剩餘折扣（依折抵後金額由大到小）

僅在第一輪結束後仍有剩餘折扣時觸發：

1. 只處理折抵後金額 > $1 的商品
2. 依折抵後金額由大到小排序，逐件補上剩餘折扣，仍須保留每件 $1
3. 若全部商品折抵後皆已剩 $1，剩餘折扣靜默丟棄

### 例外

`is_first_buy = true` 時，攤提對象縮減為前端標記的單一首購商品，其他商品不參與分配。

## 五、商品活動歸屬前置處理

折扣計算前，`PromotionCalculateDtoCache.GetProductPromotions` 已完成：

1. 查出這批購物車商品**有資格參與的活動清單**（從 Redis 查，miss 才去 DB）
2. 轉置成「活動 → 適用商品」的視角，填入每個活動的 `ProductIds`
3. 過濾掉**不在檔期內**的活動

後續的門檻判斷與折扣計算只需處理已縮範圍的資料，不需再做商品歸屬比對。
